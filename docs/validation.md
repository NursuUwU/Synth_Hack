# Проверка первой рабочей версии

Дата: 12 ноября 2026 года. Актуальные результаты v1.1: `outputs/v1_1/`, оценка: `outputs/v1_1/evaluation.json`. Первая версия сохранена отдельно в `outputs/demo/`.

## Выполнено

- Прочитан исходный архив без изменения файлов организаторов.
- Получены реальные VEP-аннотации для **3 690 уникальных вариантов**; ими покрыты все **4 096 строк** десяти случаев.
- Источник аннотации: **Ensembl release 116**, координатная система **GRCh38**, сборка источника **GRCh38.p14**.
- Загружена HPO **2026-09-01**: 20 482 термина в разобранном OBO, 9 177 профилей заболеваний в рабочем индексе.
- Все десять случаев прошли конечный запуск из локального кэша, без сети и LLM.
- Для каждого сформированы HTML, Markdown, полный JSON и TSV рейтинга. В `predictions.tsv` десять ответов; ответы hidden не проверены жюри.
- В прогоне v1.1 проверены наличие всех входных вариантов в результатах, 100% покрытия аннотациями, результаты обоих guard и совпадение хеша реализации с кодом на момент этого прогона. Добавление веб-модуля позже меняет общий хеш Python-файлов; старые отчёты сохраняют исторический хеш.
- **60 автоматических тестов прошли** на Python 3.14.10 после добавления запуска из чистого репозитория. Проверяются конвейер, адаптер GigaChat, сеть, нейтральность VUS/конфликтов, сравнение методов, чтение разметки после расчёта рейтингов, HTTP, неопределённость, запрет двух серверов на одном порту, восстановление снимка и контрольные суммы распространяемых архивов.

## Запуск из чистого репозитория

Проверено на Windows в двух отдельных папках с пробелами и Unicode в пути. В копии включались только отслеживаемые и подготовленные к добавлению исходники/resources; отсутствовали data/, outputs/, .secrets/, .runtime/ и метаданные Git. Первая проверка получила официальный Python 3.14.10 по закреплённому URL и проверила SHA-256. Вторая скрыла установленные Python из PATH и пути пользовательских установок и запретила сетевые вызовы установщика: использован ZIP Python из resources/.

В обеих копиях приложение восстановило пять файлов снимка, загрузило HPO, подняло локальный HTTP-сервер и заново рассчитало все десять случаев. У каждого 100% покрытия VEP, оба guard пройдены, полный JSON скачивается и содержит все варианты. Результаты сохраняют статусы baseline: case_05, case_08 и case_10 — uncertain, остальные — candidate. Проверки выполнены без API-ключей. Совместимость PowerShell-лаунчера дополнительно проверена в Windows PowerShell 5.1.

Воспроизведение после копирования репозитория: `python scripts/smoke_clean_checkout.py --root <папка-копии>`. Скрипт завершает только свой тестовый сервер на автоматически выбранном порту. CI `.github/workflows/startup.yml` выполняет тесты и такой же полный запуск на Windows, macOS и Linux, Python 3.11/3.14. Настройка CI сама по себе не является подтверждением прохождения удалённых заданий; результаты доступны в GitHub Actions.

Аннотация 100% означает, что каждый вариант успешно обработан VEP. Это не означает заполненность всех частот, клинических интерпретаций или других дополнительных полей.

## Локальный интерфейс

Добавлена команда `run.ps1 serve --open`. Проверены HTTP-запуск, статические файлы, поиск HPO, валидация признаков, блокировка одновременных запусков, защита от межсайтовых запросов и экспорт отдельных расчётов. Интеграционный тест вызывает исходный Pipeline: смена признака меняет ведущий ген, восстановление возвращает прежний рейтинг; исходный объект случая не изменяется. Без информативного фенотипа итоговый прогноз не назначается.

При неопределённом результате группа близких по баллу вариантов формируется по всем строкам с разрывом менее 0.025 от первого; порог общий с функцией принятия решения. Проверены включение нескольких одинаково оценённых вариантов и отсутствие такой группы при статусе `candidate`. Выбор строки для просмотра отделён от группы кандидатов цветом и текстовыми метками; сводная карточка при неопределённости показывает размер группы.

В браузере на реальных локальных аннотациях проверены case_01 (FBN1, 0.793), смена Retrognathia на явно отсутствующий признак (0.770 и изменение позиций других вариантов), поиск и добавление HP:0001250, восстановление профиля, case_05 со статусом «Конкурирующие гипотезы» и выбор карточки LMNA. Проверены широкий и узкий экраны (1440 и 390 px); ошибок JavaScript не обнаружено. Интерфейс работает без сетевых запросов к внешним API. Подробности: [interface.md](interface.md).

## Изменение симптомов и LLM

Для case_01 выполнен отдельный прогон с `examples/phenotype_override.json`: изменились позиции **111 вариантов**, изменился хеш входа; исходные файлы сохранены. Верхний вариант при этом остался тем же. Результаты — `outputs/modified/`.

Основной LLM-провайдер — GigaChat, модель `GigaChat-2-Pro`. Подтверждены два живых запроса с локально сохранённым ключом: полностью искусственный JSON-пример и, после явного разрешения пользователя, три верхних кандидата с доказательствами из учебного `case_01`. Оба ответа прошли guard. Фактическая версия модели: `GigaChat-2-Pro:2.0.30.01`. Для проверки `case_01` учтено 6 243 входных и 1 480 выходных токенов, всего 7 723. Результаты: `outputs/gigachat_synthetic_check.json` и `outputs/gigachat_case_01_check.json`.

Первоначальная ошибка соединения была вызвана отсутствием доверенной цепочки CA для GigaChat. Добавлен локальный официальный CA-bundle; TLS проверяется, системное хранилище не меняется. Ключи и OAuth-токены в результаты не записываются. Проверка OpenAI по-прежнему ограничена подставным транспортом. Инструкция — в `docs/gigachat_setup.md`.

## Что проверить предметным экспертам

**Приоритет — case_05.** Ожидаемый вариант `chr1:156138613:C:T` в LMNA присутствует в данных, но в текущем рейтинге пятый. Первым выбран UBAP2L, вторым TGFB2; разница оценок верхних кандидатов мала, поэтому статус `uncertain`.

Для LMNA на MANE Select VEP указывает `synonymous_variant` и `c.1824C>T`; другие транскрипты имеют иные последствия. Синонимичность не доказывает доброкачественность. Клиническое утверждение Ensembl выделено для нужного ALT из мультиаллельного локуса, но его привязка к конкретному заболеванию и review status отдельно не получены.

Задачи экспертов:

1. По исходной публикации из разметки проверить функциональный механизм и значимые для данного заболевания транскрипты.
2. Проверить соответствие профиля заболевания симптомам, включая исключённые признаки, и модель наследования.
3. Сравнить доказательства LMNA с верхними конкурирующими кандидатами.
4. Предложить общее правило или дополнительный источник сведений, если обнаружен пробел метода. Не добавлять исключение по идентификатору случая или варианту из ответа.

Для всей версии остаются ограничения: эвристические веса и пороги, отсутствие полноценного condition-specific импорта ClinVar/review status, частот проявления симптомов, подтверждённой фазы и семейной сегрегации. Проверки guard обеспечивают согласованность вычислений и ссылок, а не независимое подтверждение медицинской интерпретации.
